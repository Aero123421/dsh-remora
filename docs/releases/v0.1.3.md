# v0.1.3

Remora プラグインの更新結果を、自己更新による解除・再接続・DSH 再起動後も照合できるようにしました。

- 操作 ID と候補版・結果を 現在の profile 内の `.dsh-remora-updates/update-receipt.json` に保存します。他の profile や、共有 Remora 保存領域に残った操作記録は引き継ぎません。導入結果が不明なら自動で再送しません。インストール前の中断は失敗として再試行できます。
- DSH の導入版と Remora の実行版が一致したときに「更新しました」と表示します。導入済み・再起動待ちと区別し、OFF の bundle を勝手に ON にしません。
- 正式 Release のプラグイン tgz と `SHA256SUMS` だけを取得します。候補の manifest・対応 DSH・URL・redirect・checksum・受信中の累積サイズを検証します。展開せずに tgz 内の実際の package manifest を上限付きで読み、名前・候補版・bundle patch・対応 DSH が一致することも導入前に確認します。不正な SemVer を「更新なし」にしません。
- manager がない、read-only、対応版不明、開発用ディレクトリや独自名の配布物の場合は手動更新を案内します。公式 Release の URL、または導入版と同じ名前の通常ファイル `dsh-remora-<版>.tgz` からのインストールが自動更新対象です。この名前は配布経路の判断に使い、発行者の証明としては扱いません。

更新は引き続きローカルの DSH Web からだけ実行できます。CF や別 proxy 経由をローカル扱いしません。ペアリング・認証・権限・scope・緊急停止・監査設定を変更しません。CLI・hub の動作は変更せず、共通リリース規約に合わせた版番号だけを更新しています。Cloudflare へのデプロイは行っていません。

## 検証

- `pnpm typecheck`: 成功。
- `pnpm --filter dsh-remora test`: プラグインの全テスト成功。導入失敗・再起動待ち・OFF 状態・自己解除・結果不明・応答喪失・proxy 経由の拒否・候補変更・互換性・redirect・checksum・累積サイズ制限を含みます。
- `DSH_UPSTREAM_DIR=<固定 DSH checkout> pnpm pack:plugin`: v0.1.3 の公開形式 tgz を作成。配布物には実行時依存・インストール script・開発依存を含めません。
- `node e2e/run.mjs --only=browser --strict --no-pack --no-remote --dsh-dir=<DSH cache>`: npm 版 DSH 0.2.1-alpha.2 のクリーンな profile に tgz を導入し、起動後の実行版と Web 設定画面を確認。600px と 1280px のレイアウト、緊急停止と再読み込み、模擬モデルへのターンを含みます。
- `pnpm check:version`・`pnpm vendor:check`: 成功。

GitHub の公開 Release からの自己更新で実際の manager が Remora を差し替える通し経路は未検証です。導入結果・自己解除・再照合は制御した manager を使った単体テスト、公開形式 tgz の導入と実行版は実 DSH の browser smoke で確認しています。Windows・macOS の実機では未検証です。
