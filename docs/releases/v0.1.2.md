- Recheck host permissions, workspace scope and emergency-stop state after asynchronous work, before executing operations or returning results.
- Suppress delayed Hub results and approvals after access is revoked, and fix task cancellation and delivery races, including task-ID-only requests across multiple hosts.
- Prevent cancelled pairing, unpairing and disposed plugin instances from restoring stale credentials. Coordinate pairing changes between plugin instances sharing a storage directory.
- Keep settings responses from older requests or plugin instances from overwriting newer UI state, and preserve in-progress form edits.
- Validate update metadata and downloaded data, bind installation to the checked version, await the DSH installation result and report failures or required restarts accurately. Avoid duplicate installation requests and distinguish reconnects from a new DSH Host instance.

### Compatibility and upgrade

- Supported DSH range remains `>=0.2.1-alpha.2 <0.2.2-0`; the protocol version is unchanged.
- Update the plugin and restart DSH to load the new code. Existing settings remain supported; no manual settings migration is required.
- Redeploy `hub/` separately to apply the Hub fixes. Publishing this release does not update self-hosted Cloudflare deployments.
- Update status is kept for the lifetime of a DSH Host. If the Host restarts during installation, the UI reports an unknown result; check the installed version before retrying.

### Validation

- 436 automated tests across the protocol, plugin, CLI and Hub, including regression tests for authorization, pairing, task delivery and updates.
- 15 compatibility tests against the pinned DSH source.
- 43 strict end-to-end checks using DSH 0.2.1-alpha.2, Chromium and a local Hub, with a mock model provider.
- Type checks, builds, protocol vendor consistency and plugin packaging checks.

Live ChatGPT/Claude connections, production Cloudflare deployments and real model-provider calls are outside these local checks.
