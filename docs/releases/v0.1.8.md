# v0.1.8

DSH 0.2.2-alpha.2 の履歴 API と application consent に対応し、ハブの並行処理と設定画面などを修正します。

## 変更

- DSH の新しい `events()` API を使ったページ付きの履歴読取に対応します。旧版の `inspect()` も引き続き使います。application consent は無関係な質問として保留せず、DSH の承認 UI に渡します。DSH peer 範囲は `>=0.2.1-alpha.2 <=0.2.2-alpha.2` です。
- 接続停止やセッションの範囲外・未信頼・アーカイブなどで外部回答できなくなった保留中の質問・承認を DSH の回答者へ戻します。一時的な接続断では保留を維持します。
- ハブ監査ログの並行追記を再試行し、リカバリーコードの再発行を原子的に行います。存在しないパスキーの削除表示、承認の許可・拒否プレビュー、夏時間で存在しない時刻も修正します。
- 接続設定のハブ URL を消して編集できるようにし、禁止コマンドの保存を拒否し、残り時間の単位を翻訳します。CLI の日付のみの指定と Windows DPAPI 出力の読み取りを修正します。
- ハブから未使用の MCP SDK を除き、開発用 vitest を 4.1.12 に更新します。

## 更新と注意

プラグイン、CLI、ハブは同じ 0.1.8 です。ハブの修正を使うには、ハブ側の upstream-sync または再デプロイが必要です。このリリースは npm や Cloudflare へ自動デプロイしません。

pnpm 12 でプラグインを追加・更新する際、公開後 24 時間未満の依存を含む lockfile は `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` で失敗し、同じプロファイルの `node_modules` が空になることがあります。運用プロファイルを更新する前にバックアップし、pnpm 10 を使ってください。既に壊れた場合は pnpm 10 で `dsh plugin --profile web install` を実行します。これは DSH/pnpm 側の既知の問題で、本リリースでは修正していません。

ハブの認証失敗では、従来どおり本文が空の HTTP 401 が返る場合があります。プラグインは Release 添付の tarball URL から導入してください。

## 検証と限界

Linux / Node 22 で型検査、plugin・protocol・CLI のテスト、ハブの単体・Cloudflare Workers 結合テストと dry-run、パックを確認しました。リカバリーコードの INSERT 失敗を実際の Durable Object SQLite に注入し、旧コードのロールバックと重複要求を確認しました。監査ログは 32 件の同時追記・同時 RPC とハッシュ連鎖、失敗後の次の追記を検証しました。

統合ソースから版上げ前に作成した 0.1.7 名義の検証用 tarball を、公式 npm 版 DSH `0.2.1-alpha.2` と `0.2.2-alpha.2` の隔離プロファイルに導入し、各々 strict E2E の 45 項目が成功しました。モデルは模擬応答、パスキーは仮想認証器、ハブはローカル Workers です。リリース workflow は版上げ後の tarball でも両端の strict E2E を実施します。

DSH の互換検証には模擬モデルと一部スタブを使用します。実アカウント、実 MCP クライアント、Cloudflare 本番、実電話の Web Push、全 OS、実機 Windows の DPAPI、有料推論と全機能の組合せは未検証です。DSH の範囲外の新バージョンはこのリリースでは保証しません。
