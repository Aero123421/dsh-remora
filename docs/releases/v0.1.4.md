# v0.1.4

自己更新でプラグインが消えたときの入れ直しと、ハブが再接続時に未確認タスクを尋ねる範囲を定めました。

- 取り外しが例外で終わったとき、`stop-profile` 以外の失敗でプラグインが一覧から消えているとき、または外したあとの導入が失敗・中止・上書き・例外でプラグインが無いときは、外す前の配布元を別の導入 ID で入れ直します。一覧に残っている失敗はそのまま返し、一覧を読めないときは前の版を入れません。
- 「前の版を入れ直した」と表示するのは、bundle 名が `dsh-remora` で、版と package の結果が前の版と一致するときだけです。結果に版が無いときは、一覧がその版を示していることを確認します。
- 入れ直しの request id と前の版を `update-receipt.json` に追加します。schema は 1 のままで、v0.1.3 はこの追加項目を無視して読めます。入れ直しの途中で v0.1.3 に戻すと、その ID は追わず、元の導入 ID の結果で確定します。
- ハブは、送ったが結果が届いていないタスクを、再接続のたびに 8 件までホストへ尋ねます。未確認になってから 10 回、または 24 時間を過ぎると尋ねるのをやめ、実行された可能性があるのでマシンを確認するよう記録します。一度も送っていないタスクの「届いていない」とは分けます。
- オーナーが確認画面を経由せず直接確認した `terminal.run` も、コマンドの制限時間に 30 秒を足した grant の期限まで待ちます。他の操作の待ち時間は 20 秒のままです。
- 起動時にセッションの読み取りが一時的に失敗しても、そのセッションの未回答の attention は消さず、ハブの既存の行を残します。セッションが削除されていたときは、これまでどおり消します。

CLI と hub の版番号も 0.1.4 です。動作の変更はプラグインの自己更新と、ハブの再接続・確認待ち・attention です。Cloudflare へのデプロイは行っていません。設定・資格情報・権限の保存形式は変えていません。

## 検証

コマンドと結果は、この版の PR の検証表に記録します。
