# 文書の翻訳

対象言語、元文書、翻訳する範囲を依頼・既存の公開方針から決めます。普通の文書修正で中国語や英語のpairを自動的に作りません。

## 翻訳する情報

操作、actor、条件、例外、順序、失敗、互換性、検証範囲を保ち、対象言語で自然な文章にします。code、command、package名、wire token、利用者の入力は、説明文と区別してそのまま扱います。

用語は対象リポジトリのUI・辞書・既存文書に合わせます。元文書に曖昧な条件があれば、推測を翻訳で確定せず、所有sourceを確認します。

## 既存の翻訳を更新する

変更された命題と、それに対応する段落を直します。無関係な全文の再翻訳やfileの再構成へ広げません。機械的なcode・path変更は意味と参照先を照合します。

翻訳pairの独自metadata・hash・gateがあるリポジトリはその手順に従います。ないリポジトリへ、同期のためだけに新しい仕組みを追加しません。

## 確認

両言語の条件・失敗・操作とリンクを読み比べます。元の作者報告や未検証の内容を、翻訳で実行済みの成功へ変えません。

UIの翻訳はtyped dictionaryやそのpluginのlocaleへ置きます。DSHのシステムプロンプト、モデルの応答言語、toolの動作を翻訳作業だけで変えません。
