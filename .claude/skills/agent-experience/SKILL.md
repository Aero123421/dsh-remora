# エージェント向けの情報設計

利用目的、操作、制約を最初に見える場所へ置き、細部は必要なときに取得できる形にします。認証・破壊的操作・検証の条件は、その操作より前に分かるようにします。

## ツール定義

- 名前と説明は、何をするか・何が返るかを表します。内部の実装や、返却結果から分かる規則を説明へ重ねません。
- 引数のdefault、範囲、組合せ、指定する条件は、その引数のschema・descriptionへ置きます。
- 設定によって変わる内容を固定のtool説明へ隠しません。必要なら入力・能力情報として扱います。
- 同じ規則をtool説明、prompt section、別のtoolへ重複させません。実行の判断に必要な事実は残します。

## 発見と結果

遅延読込する資料・tool・追加機能には、意味のある説明と取得手段を用意します。register成功だけで実agentから見えると判断せず、scopeとschemaを確認します。

大きな結果は件数・識別子・取得先を返し、省略範囲を示します。隣接する情報が次の操作を減らす場合は、必要な分を含めます。短い結果でも再検索・再読込・誤りが増えるなら、情報を削り過ぎています。

変更前後のtool定義やfirst-turn prompt量を比較できる場合は計測します。token量の減少と、目的を達成できることを別に確認します。modelのpersonaや応答言語を、この整理に紛れて変更しません。
