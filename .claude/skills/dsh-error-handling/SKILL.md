# 失敗と復旧

失敗ごとに、処理の所有者、実行済みの副作用、現在状態、次に安全にできる操作を決めます。catchで例外が止まったことは、状態が戻ったことの証明ではありません。

## 結果を区別する

想定する失敗は安定したtag・型と必要な詳細で返します。判定を人向けmessageの文字列解析へ依存させません。原因を保ち、Clientの表示文言と内部の識別を分けます。

副作用なし、部分完了、commit済み、結果不明を区別します。更新後の通信切断や外部送信後の保存失敗を、一律の失敗や安全なrollbackに変換しません。

## 再試行と取消

再試行の回数・期限・取消は、処理の寿命に合わせて決めます。書込み・送信・導入など副作用がある処理では、同一操作の識別、重複防止、結果照合も扱います。同じ処理を再起動後も再開する場合は、消費済みの再試行回数と、設定した上限・期限を保持します。

取消を受け付けたこと、処理を止めたこと、保存・子processの終了は別に観測します。background処理にも所有する寿命と、失敗を伝える経路を持たせます。

無関係なSessionへ続けられる障害は、その範囲に封じます。権限や保存状態が検証不能な処理は、成功へ変換せず依存する操作を止めます。

## 表示と検証

読みやすい要約、影響した操作、安全な次の行動をlocaleへ出します。未知の結果は未知と表示し、reportの失敗に別の観測手段を持たせます。エラーや診断にはsecretやsecret付きURLを含めません。認証に必要なURLを案内する場合は、その認証操作の表示と診断出力を分けます。

テストは例外をcatchしたかだけでなく、最終状態、登録・資源、保存、利用者への表示を確認します。
