# 文章の整理

依頼されたfile・差分・作業の範囲で、意味と根拠を確認します。レビューだけなら指摘し、編集が依頼された場合は修正します。

## 残す情報

誰が何をするか、条件、例外、順序、所有者、失敗、副作用、互換性を残します。短い表現でそれらが落ちるなら、具体的に書き直します。

コメントはコードだけでは分からない制約・理由へ置きます。public APIは入力、結果、失敗、取消、保存・外部副作用の必要な契約を説明します。実装の行順を言い換えるだけのコメントは削ります。

## 削る情報

同じ説明の繰返し、抽象的な賛辞、作業中の独白、レビューの応酬、未公開draftへの参照を削ります。単語の一律禁止や機械的な字数制限で、必要な事実を削らないようにします。

## 所有者と確認

コメント・辞書・generator等のsourceを先に直し、派生資料はそれから更新します。第三者の取り込みと歴史資料は、対象の編集方針を確認します。

UI copyとmodel向け説明は動作に影響します。条件やtoolの使い分けを変えず、必要な期待値を確認します。日本語化だけでモデルへの応答言語の指示を足しません。

修正後のdiffで意味の欠落を確認し、実施した検証と残した理由を報告します。
